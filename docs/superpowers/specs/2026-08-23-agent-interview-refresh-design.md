# Agent 面经重置与持续加权设计

## 目标

把 Agent Journey 的公开面经从历史前端题单重置为可追溯的真实 Agent / AI 工程面经，并让后续每次采集都能幂等去重、给重复出现的知识点累计热度，为内容更新和后续自媒体选题保留结构化证据。

## 已确认的产品口径

- 面经模块只保留与 Agent、AI 应用、Agent 相关后端工程直接相关的真实面试经历。
- 旧的 34 篇无来源前端面经下线；无可核验 URL 的 Agent Skill 专题面经下线，其有效知识内容继续保留在知识库。
- 保留已发布且可核验的 2 篇字节面经，再新增 10 篇可核验面经。
- “新增 10 篇”指新进入 Agent Journey 的公开内容。真实性与岗位相关性优先于发布时间；不使用推广、代面、纯题库或无过程证据的帖子凑数。
- 本批来源覆盖字节 3 篇、腾讯 4 篇、蚂蚁 3 篇。当前没有达到同等证据门槛的阿里样本，作为覆盖缺口记录，不伪造补齐。

## 去重与记录

采集层继续使用稳定 URL ID、正文指纹、问题指纹和 SimHash。SimHash 近似匹配必须受来源上下文约束：牛客帖子只有在公司和作者均一致时才允许仅凭近似正文合并；正文完全一致仍可跨 URL 合并。这样既阻止转载重复，也不会把不同公司的常见八股误判成同一篇。

发布层新增受 Git 管理的 `.codex/interview-source-history.json`。每个来源保存 URL、内容 ID、内容指纹、问题簇、证据等级、处置状态、公开文章 key、关联知识点 key 和时间。相同 URL 且内容未变时跳过；相同 URL 内容变化时更新；相同问题簇的新 URL 合并来源；一个问题簇最多对应一篇公开面经。

## 知识热度

知识点不按题目措辞新建同义文章。每篇面经用 `clusterId` 作为一次独立证据：

- 已有知识点命中时，登记反链并把 `heat` 增加一次；同一 cluster 重跑不重复增加。
- 新面经带来新的工程角度时，补充既有正文；没有新角度时只加权。
- `currRank` 按现有分档重算，受影响兄弟节点按 `heat` 降序稳定排序。
- 来源历史中的 `knowledgeKeys` 可按公司、日期和知识点聚合，后续可直接生成高频考点榜、公司差异和自媒体选题候选。

## 发布与验收

- Data Collector 修复去重并重建本机候选索引。
- 内容仓库删除旧面经、发布 10 篇新面经、更新知识点及来源历史。
- 两仓测试、树校验、链接/隐私扫描和 diff 检查全部通过后提交并推送 `master`。
- 等待 `front-end-journey-resource` 的 `sync-content` Action 成功，再以线上导航和文章读取做冒烟。

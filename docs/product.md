# Data Collector 0.1.0 产品方案

## 目标与原则

产品解决的是“把浏览器里已经能看到的内容，低摩擦地变成结构化知识资产”。首版成功标准不是做一个通用爬虫，而是稳定覆盖两个高价值来源、保证来源可追溯、重复采集可更新，并为后续接入知识库或业务系统留下接口。

核心原则：本机优先、最小权限、显式失败、离线可用、稳定幂等。

## 用户路径

### 页面内保存

1. 用户在 Chrome 打开微信公众号文章或已登录的知识星球详情页。
2. 点击 Data Collector，确认当前来源后保存。
3. 扩展显示识别页面、提取正文、归纳内容、写入本机四个阶段。
4. 完成页展示目标文件路径，可复制或在文件夹中查看；失败页可以直接重新保存。

### Codex 自动采集

1. 用户把 URL 发给 Codex。
2. Codex 执行 `npm run collector -- collect '<URL>' --wait 60000`。
3. 本机 Bridge 校验地址并通过已认证 WebSocket 派发任务。
4. 扩展在后台标签打开页面，使用用户现有浏览器会话提取内容。
5. Bridge 整理、落盘，只向 Codex 返回最终绝对路径。

需要验证码、登录或页面确认时，任务进入 `needs_attention`，不会尝试绕过站点访问控制。

## 信息模型

统一内容模型包含：

- 来源：`wechat | zsxq`
- 类型：`article | post | question | answer`
- 原始 URL 与去跟踪参数后的规范 URL
- 标题、作者、发布时间、采集时间
- 正文 HTML、纯文本、图片
- 来源建议与用户指定的分类、标签
- 少量非敏感来源元数据

写入前进行 schema 校验、HTML 白名单清洗和本地离线组织。摘要不超过 280 个中文字符；分类使用可解释的规则；标签来自标题/正文关键词和明确的用户输入。该取舍让首版没有模型 API、费用和隐私依赖，未来可替换组织器而不改变采集协议。

## 来源策略

### 微信公众号

当前识别官方文章详情域名 `mp.weixin.qq.com`，使用 `#activity-name`、`#js_name`、`#publish_time`、`#js_content` 等稳定页面语义。正文过短或容器缺失时明确失败。

### 知识星球

支持 `wx.zsxq.com` 及其子域的文章、动态、问答详情。优先使用语义化 `data-testid` 与常见详情容器；仅在存在唯一高置信度正文块时使用评分回退。检测到登录页会提示用户登录。首版不保存 Cookie、令牌或整页网络流量。

## 本地知识库

条目按“来源/分类/年份/稳定 ID + 标题”组织。稳定 ID 来自规范 URL 的 SHA-256 前 12 位，因此同一内容重复采集会更新原路径。写入使用同目录临时文件、同步和原子重命名，避免进程中断留下半个文件。

图片限制为每篇最多 30 张、单张最多 10 MB、10 秒超时；只下载解析到公开 IP 的 HTTPS 位图，每一跳重定向都重新校验，并以内容哈希命名去重。失败时保留远程地址并记录数量，不阻止正文落盘。

## 0.1.0 范围外

- 不绕过登录、付费墙、验证码或站点访问控制。
- 不做批量历史爬取、定时爬取或全网通用正文抽取。
- 不采集评论、点赞列表、Cookie、LocalStorage 或用户密码。
- 不自动上传云端或调用外部大模型。
- 不改动 `~/Code/midway/fe-journey-faas`；后续接入需新增用户可见、可撤销的保存目标与凭证管理。

## 后续演进

1. 可插拔 `LibrarySink`：本机目录、fe-journey-faas、Notion 或产品知识库。
2. 用户可编辑的分类规则和来源模板。
3. 本机全文索引、差异更新和版本历史。
4. 可选的本地/云端模型摘要，默认继续保持离线。
5. 更多来源时仍采用显式域名和专用提取器，不引入无限制 `<all_urls>` 权限。

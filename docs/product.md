# Data Collector 0.2.0 产品方案

## 目标与原则

产品解决“把浏览器里已经能看到的内容，低摩擦地变成结构化知识资产”。0.2.0 稳定覆盖微信公众号和知识星球，保证来源可追溯、重复采集可更新，并用 Edge Side Panel 提供持续可见的本机采集入口。

核心原则：本机优先、最小权限、固定身份、自动授权、显式失败、稳定幂等。

## 用户路径

### Side Panel 保存

1. 用户在 Edge 打开微信公众号文章或已登录的知识星球详情页。
2. 点击 Data Collector 工具栏图标；后台已配置 `openPanelOnActionClick`，Edge 一步打开 Side Panel。
3. 固定扩展身份自动连接本机 Bridge；用户不输入连接信息。
4. 用户确认当前来源、可选编辑分类和标签，再点击“保存这一页”。
5. 扩展直接从当前 tab 提取并回传，不为同一页面再打开后台采集 tab；Side Panel 持续显示识别页面、清理正文、归纳内容、写入本机四个阶段。
6. 完成页展示目标文件路径，可复制或在文件夹中查看；失败页可以直接重新保存。

Side Panel 保持打开时会轮询本机连接与任务状态，因此页面切换、后台采集和错误恢复都有明确反馈。

### Side Panel 批量保存（知识星球列表页）

1. 用户停在知识星球的分组 / 分类 / 精华页；Side Panel 识别为列表页，按钮变为“批量保存本页帖子”。
2. 点击后逐条提取本屏帖子，每条按自己的详情地址建任务入库；面板实时累计“已入库 / 已跳过 / 失败”。
3. 一屏采完自动收起已处理的帖子并滚动加载下一批，直到没有新内容或到达上限（60 条 / 12 轮）。
4. 结束页可以“继续采下一批”或“完成”。整批过程中不新开标签页。

### Codex 自动采集

1. 用户把 URL 发给 Codex。
2. Codex 执行 `npm run collector -- collect '<URL>' --wait 60000`。
3. Bridge 校验地址并通过已认证 WebSocket 派发任务。
4. 扩展在后台标签打开页面，使用用户现有浏览器会话提取内容。
5. Bridge 整理、落盘，只向 Codex 返回最终绝对路径。

需要验证码、登录或页面确认时，任务进入 `needs_attention`，不会尝试绕过站点访问控制。

## 固定身份与首次连接

manifest 的固定公钥派生稳定扩展 ID。新安装先读取 Bridge 健康信息并核对受信任 ID，再通过固定扩展 Origin 自动取得 bearer token。该流程把一次人工连接步骤改成发布身份校验：普通网页和其他扩展会被 Origin 拒绝，但同用户本机恶意软件不在威胁模型内。

旧版安装的 ID 不会因“重新加载”而改变。升级 0.2.0 必须先在 `edge://extensions` 删除旧 Data Collector，再从 `artifacts/data-collector-extension` 重新加载；产品在身份不匹配时展示这条恢复路径。

同一 Bridge 同时只服务最新浏览器实例。新实例接管后，旧实例明确显示“另一个浏览器实例已接管”并进入 standby，不自动反复争抢；用户可在旧实例中显式重试并重新接管。

## 信息模型

统一内容模型包含来源、类型、原始 URL、规范 URL、标题、作者、发布时间、采集时间、正文 HTML、纯文本、图片、分类、标签和少量非敏感来源元数据。

写入前进行 schema 校验、HTML 白名单清洗和本地离线组织。摘要不超过 280 个中文字符；用户输入的分类和标签优先。0.2.0 不依赖模型 API、费用或云端隐私承诺。

## 来源策略

### 微信公众号

识别 `mp.weixin.qq.com` 官方文章详情，使用 `#activity-name`、`#js_name`、`#publish_time`、`#js_content` 等页面语义。正文过短或容器缺失时明确失败。

### 知识星球

支持 `wx.zsxq.com` 及其子域的文章、动态、问答详情。每条帖子对应一个 `.topic-container`，正文取其中的内容容器（评论天然被排除）；站点 `<title>` 恒为“<星球名>-知识星球”，标题由正文首句派生。检测到登录页会提示用户登录，不保存 Cookie、令牌或整页网络流量。

帖子号不在列表页 DOM 上（无链接、无 data-\*、整棵子树没有长数字），扩展在页面主世界旁观
应用自己的接口响应，从中取出 `topic_id` 与正文，再按正文把页面节点对回帖子号。只读页面已经
发出的响应，不额外发请求、不读 Cookie，只保留帖子号与对号所需的正文。

列表页（分组 / 分类 / 精华，地址里没有 `/topic/`）不作为一篇保存——那会把整屏帖子糊成一条——而是走**批量保存**：逐条提取，每条按自己的 `/topic/` 地址建条目；采完一屏把已处理的帖子收起并滚动加载下一批，直到没有新内容。拿不到自身链接的帖子计入“已跳过”，绝不退回用列表页地址（否则同一 ID 会相互覆盖）。这是用户主动触发的当前页操作，不是后台历史爬取。

## 本地知识库

条目按“来源/分类/年份/稳定 ID + 标题”组织。稳定 ID 来自规范 URL 的 SHA-256 前 12 位，同一内容重复采集会更新原路径。写入使用同目录临时文件、同步和原子重命名。

图片限制为每篇最多 30 张、单张最多 10 MB、10 秒超时；只下载解析到公开 IP 的 HTTPS 位图，每一跳重定向都重新校验，并以内容哈希命名去重。失败时保留远程地址并记录数量，不阻止正文落盘。

## 0.2.0 范围外

- 不绕过登录、付费墙、验证码或站点访问控制。
- 不做批量历史爬取、定时爬取或全网通用正文抽取。
- 不采集评论、点赞列表、Cookie、LocalStorage 或用户密码。
- 不自动上传云端或调用外部大模型。
- 不防御已控制同一用户账户的本机恶意软件。
- 不改动 `~/Code/midway/fe-journey-faas`；后续接入需要用户可见、可撤销的保存目标与独立凭证管理。

## 后续演进

1. 可插拔 `ContentSink` 与来源路由（已落地）：本机 Markdown 库 + 目标仓库收件箱（`repo-inbox`），凭证只在 Bridge。见 [落地目标与来源路由](sinks.md)。
2. 用户可编辑的分类规则和来源模板。
3. 本机全文索引、差异更新和版本历史。
4. 可选的本地或云端模型摘要，默认继续保持离线。
5. 更多来源仍采用显式域名和专用提取器，不引入无限制 `<all_urls>` 权限。

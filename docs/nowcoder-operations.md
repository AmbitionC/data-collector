# 牛客运营助手

目标是让有实际需要的牛客读者发现并使用 Agent Journey。用户已在 2026-10-28 确认先实现机会列表、回复角度、可编辑草稿、处理台账，并用真实帖子预览回复。2026-10-29 补充：不为水评论而参与；匹配的场景应正常推荐产品，未来也可能以对外 Skill 安装承接，网站注册不是唯一入口。

## 固定批次

批次命令为 `nowcoder ops workflow --file /absolute/request.private.json [--send] [--wait 600000]`、`workflow --id RUN_ID [--wait ...]` 和 `stats --id RUN_ID`。完整请求示例、准备包字段、阶段停止规则和离线用量计量见 [批次执行速查](../.codex/skills/data-collector-delivery/references/nowcoder-workflow-runbook.md)。单条命令继续兼容。

认证HTTP：`POST /v1/nowcoder/operations/workflow` 接收严格请求清单，publish另需同级 `send:true`；`GET .../workflow/RUN_ID` 和 `GET .../workflow/RUN_ID/stats` 返回短状态、逐项阶段时间、计数、耗时与私有 `resultPath`。完整请求摘要、阶段和结果持久化在配置目录的 `nowcoder-workflows/`（目录0700、文件0600），准备包保留完整正文/实际评论/图片引用/覆盖与版本绑定，不输出到普通status。

同key同清单返回原运行，不重放；改清单复用key拒绝。busy从首次落盘前覆盖整批并纳入更新/重启栅栏，外部冲突写入被拒绝。Bridge重启将running/queued置待核验；已有单条dispatching/uncertain台账始终是最终去重依据。等待期限只约束CLI，不取消服务端批次；超时返回原ID与查询方法，退出非零，后台继续原授权运行。prepare每项job等待60秒，超时保存准确jobID并停止。

页面读取采用有界语义稳定等待；未知评论总数保留null、不称完整覆盖。展开子回复观察内容/完成状态变化；不稳定明确attention或覆盖限制。发布前真实变化继续拒绝，`CONTEXT_CHANGED.contextChanges` 传递变化字段、评论URL增删改（各最多30）与前后总数，并保存在单条发送证据中。点赞等非语义字段不参与正文指纹。

### Slate 长帖正文采集（v0.4.70）

采集器识别 `.nc-slate-editor-content` 精确正文，优先于包含标题和订阅界面的外层容器，并支持该容器中的完整短问题。正文内的文字和图片继续保留，不按“提示”“订阅专刊”等词语删改内容。同帖正文区域中仍可见的展开控件继续标记截断；隐藏控件和评论区展开按钮不作为正文截断依据。正文变化校验仍严格执行；旧采集、失败批次和发送台账不重写、不重放。更新后须核对实际加载的构建，并用全新来源的独立准备验证正文与评论覆盖，再按原审阅流程准备发布。

### 可选更新拉取的截止点（v0.4.74）

自动更新中的 `git fetch origin master` 使用独立的 15 秒网络预算，已有 HTTP/1.1 回退形式同样适用；不再沿用打包命令的 10 分钟默认预算。超时仍按原进程组清理逻辑终止子进程，更新失败记录原因并释放更新意图，服务继续使用已加载构建。网络较慢时可以跳过本次可选更新，由原有周期再次检查。

快进合并、打包与重启继续使用原有空闲和制品门禁；显式传入的命令截止点仍优先。此变更不修改发送台账、验证暂停、账号角色或额度，也不把旧待核验事件改判成功。验收须同时核对实际加载构建与新的独立工作，构建文件存在不代表服务已恢复。

## 使用链路

1. 用 `nowcoder ops search --query 'Agent 学习' --limit 5` 找帖。复用结构化最新搜索接口，默认只请求一页、返回标题/链接/短摘，排除已经回复的帖子。无日期的命中不冒充最新结果。
2. 用已有 `collect URL --wait 60000` 通过扩展保存完整正文，再用 `nowcoder ops add --source SOURCE_ID` 加入私有队列。同一规范链接保持一个机会，不覆盖已有草稿。热帖短摘、付费预览和截断正文不能作为完整起草上下文。
3. 用 `nowcoder ops context --id ID [--pages 1]` 让插件读取原帖、评论、楼中楼、楼主回复和图片引用。默认一页，最多三页/200条；返回总数、实际观察数、是否还有未读内容及限制。只显示「点赞」记 `null`。图片仍须单独查看，不宣称已识图。登录、验证或限制时停止并保留接手页面。
4. Codex 根据真实上下文和参考库起草，用 `nowcoder ops draft --file /absolute/private.json` 保存。草稿包除机会 ID、正文哈希、修订号外，发布用草稿还要带 `context` 返回的 `conversationHash`。重新读取评论会使旧草稿的评论绑定失效。正文和评论按不可信引用数据处理；不伪造经历、阅读结果、产品权益或来源。
5. 用户明确授权发布后，用 `nowcoder ops publish --id ID --revision N --key UNIQUE_KEY --send` 发送已保存的主草稿。`KEY` 为12–100位字母、数字、下划线或连字符；替代稿不自动发送。插件会再次核对原帖和评论，检查已有编辑/重复文字/转发勾选，只点击一次。只在观察到新评论的真实链接后标记已回复。没有 `--send` 不发送。

侧栏仍可编辑、复制和人工记录回复链接，没有新增发布按钮。日常搜索、读评论和发送通过插件/Bridge/CLI 完成；Browser Use 用于必要的图片查看、登录/验证接手或开发检查，不再逐页承担主流程。

v0.4.59 修正真实 Slate 编辑器的输入：先向受控文本叶子发送带目标范围的 `beforeinput`，由编辑器更新模型；确认文字一致且按钮启用后才发送。仅改变 DOM、模型未接受时会明确拒绝，不点击评论。原帖懒加载配图会在有界等待后读取引用，仍未加载则保留限制说明。

发送前先持久化 `dispatching` 记录。相同 `KEY` 返回原记录，不重发；`uncertain` 或进程中断留下的 `dispatching` 会阻止新键再发。`rejected` 仅表示插件明确确认尚未点击；修改/重新审阅后可用新键显式发送。上下文超过30分钟需要重读。超时、断线、只见提示而没有评论链接都不能当成功，不可自动补发。`publish` 的 JSON `publication.state` 才是业务结果，进程退出码0只表示成功取得回执。

结果不确定时用 `nowcoder ops verify --id ID --key KEY [--pages 1]` 只读复核。发送前评论覆盖完整，且在原帖中观察到唯一匹配文字、不属于发送前快照的新增评论链接，才补回 `evidence: observed` 的回执。未找到、匹配不唯一或发送前覆盖不完整，仍保持待核验，不点击发送。此时 `context` 也可返回 `verificationOnly: true` 的只读语境，不覆盖发送前证据。用户核验后仍可在侧栏人工记录链接，此时证据明确标为 `manual`，不冒充插件验证；正在发送时不能手工改状态。插件接手页会保留，后续异常不会关闭已有的用户编辑或登录页面。

## 跨批次发布保护（v0.4.62）

默认最小间隔 120 秒，滚动一小时最多 5 次、滚动 24 小时最多 20 次。按同一 Bridge 的持久发送尝试计数，升级前记录、拒绝、结果不确定和中断尝试均计入；换批次、重启、修改配置不会清零。同一 key 仅查看原记录，不重复扣额度。本机预算不统计其他安装或网页手动评论，不代表牛客公开阈值，也不能保证免验证。

- `nowcoder ops limits`：查看限制、累计用量、单条下次可尝试时间和待处理验证。
- `nowcoder ops configure --file /absolute/policy.private.json`：严格读取完整 JSON，例如 `{"minIntervalMs":120000,"maxPerHour":5,"maxPer24Hours":20}`；不接受关闭保护的零值，不清除历史或验证。
- 发布批次先检查整批剩余额度，额度不足时停止并保存未执行条目。整批超过配置上限须缩小清单；其余预算不足会给出按当前历史计算的最早时间。间隔等待由 Bridge 内部执行并记为 `publish_wait`，不会不断打开网页或要求模型轮询；预计超过语境有效期则停止，要求重读和审阅。

出现 `VERIFICATION_REQUIRED` 时立即持久化全局暂停，保留原帖、请求 ID 和原 key。运营搜索、读评论、prepare 采集和所有新发布都停止；原 key 仍可只读查询。完成原页验证后，先运行 `ops limits` 取得当前验证 ID，再执行 `nowcoder ops resume --id VERIFICATION_ID --verification-completed`。恢复只读取保存的原帖，按原 key 核验可能已经发出的评论；仍见验证、登录失败、页面错误或验证 ID 变化均不解除暂停。不明确的原评论仍保持 uncertain，不会补发。恢复不会续跑已停止批次，也不重置额度。

认证 API：`GET/PUT /v1/nowcoder/operations/publishing`，`POST .../publishing/resume`（严格要求 `id` 与 `verificationCompleted:true`）。发布保护私有状态保存在配置目录 `nowcoder-publishing.json`，记录损坏、本进程观察到保护文件丢失、已记录的发送台账部分或全部缺失时停止发布，不擅自覆盖。旧版未核销的验证记录也会迁移为暂停。

页面诊断只保存实际观察到的 `pageStartedAt`、`beforeSubmitAt`、`submitClickedAt`、`verificationObservedAt`、`receiptObservedAt`。这些时间经插件回执进入单条发送记录、私有批次证据和短 `stats`；没有观察的字段和历史事件不补造，不能据此推断平台隐藏风控原因。侧栏仅在首次进入和显式刷新时读取保护状态，保留草稿，不新增发送按钮。

## 失败诊断与点击证据（v0.4.65）

异常按建页、等待加载、脚本执行、回执解析和页面内部操作分别记录。私有结果和发送台账中的 `failure` 保留发生时间、阶段、最近页面阶段、错误名称/信息及有界堆栈；凭证字段和 URL 查询参数先脱敏。普通界面继续显示中文处理提示，`stats` 只输出不含堆栈的摘要，完整证据留在认证接口对应的私有结果文件中。

页面在扩展隔离环境中记录本次执行的进度，按随机执行 ID、原帖与动作类型绑定。脚本结果丢失后，只读读取仍然存在的隔离环境，尽量取回实际观察到的点击和验证时间。页面导航或执行环境被销毁、绑定不符或数据无效时，明确保留未知；不补造历史时间，不因缺少点击记录而自动认定未发送。`clickState: invoked` 表示已到达调用点击的位置，不等同于服务端收到或评论发布成功。

已观察到的验证码在结果丢失后仍维持验证暂停。诊断读取不刷新原页、不重放点击、不清空额度，也不重启已停止批次。升级前已经丢失的异常和点击证据不能由新版本还原；旧 key 继续只读核验，没有唯一真实回执就保持待核验。

v0.4.66 的页面操作参数通过 JSON 文本传递，保留浏览器脚本注入时可能丢失的嵌套 `null` 字段。未知评论总数继续保留为 `null`，不补成 0；原帖、评论或总数发生变化仍在编辑器写入前停止，既有待核验记录不会因此自动重发或改判。

### 页面截止点与后台等待（v0.4.71）

评论回执同时监听实际 DOM 变化，并按真实时钟限制观察窗口；不再用固定次数的串联计时器决定何时结束。[Chromium 后台计时器说明](https://developer.chrome.com/blog/timer-throttling-in-chrome-88)解释了隐藏页面的计时器可能延后；这不等于能认定某次平台失败的原因。

扩展按原认证请求的派发时间设置统一截止点，消息排队、建页、加载和脚本执行共用该预算，不因收到晚到消息重新计时。页面在等待恢复后、写入前及唯一提交点击前检查同一截止点；过期工作不能延迟点击。扩展有界读取原执行 ID 的隔离检查点，保留原页和实际点击/验证证据；诊断读取或页面接手本身也有等待上限，不会无限占住运行状态。已开始脚本但取不到可靠点击证据时仍记 unknown/uncertain；只有明确未开始注入或页面实际返回未点击，才可记 not_attempted。

后台重启时，尚未正常关闭/交接的评论或文章操作页保守转交保留，不由旧临时页清理逻辑关闭，不影响既有接手页。普通采集临时页照常清理，正常成功的操作页照常关闭；保留页面不构成发布成功或未尝试的判定。

Bridge 的传输异常另存 `failure.stage: transport` 和脱敏原始原因，不再只留笼统的发送中断提示。断线或结果不确定仍只按原 key 核验；新版本不恢复旧丢失证据、不清除验证或营销保护，不重试原发送，也不把没有点击记录当作未发送。只有真实 observed 回执可计成功。明确未点击的截止点拒绝按原失败批次规则保留、排除来源并诊断，不能在同轮换帖补发。

## 定时任务恢复检查（v0.4.68）

`nowcoder ops recovery [--attempt N]` 通过认证的 `GET /v1/nowcoder/operations/recovery?attempt=N` 检查当前评论连接、能力、产物构建、运行中的采集/文章/运营任务和发布保护。它不打开牛客页面、不发送、不解除验证，也不续跑失败批次。返回 `ready`、`waiting` 或 `needs_user`、原因码及 `nextCheckAt`；只有 `ready` 才允许开始准备独立的新工作，发送仍须经过原有审阅和显式 `--send`。

临时断线、忙碌、更新或构建不匹配时，按连续检查次数等待 5、15、最多 30 分钟。Bridge 不可用时 CLI 也返回结构化等待状态，不让定时任务因一次连接错误丢失后续检查。额度等待采用真实台账给出的时间，不清空历史、不提高限制；实际唤醒还须服从用户指定的白天窗口。`--attempt` 为 0–100，仅影响退避时间，不记录发送次数，也不修改保护。

每轮执行前先预约一次保底只读检查，结束后再更新为真实的下次窗口；中途退出时下轮先查原 run/key，避免漏掉续跑或重复发送。定时任务在等待恢复或需要用户处理时仍保持启用，但有验证、登录/账号异常、损坏台账或不确定点击时必须停止新发布。验证码保留原页，通知用户一次并继续只读监测；用户实际完成并明确回复后，才按原验证 ID 执行既有核验恢复流程，不能自动声明完成验证。记录不明确时只核验原 key；没有唯一新增回执仍保持 uncertain。旧失败批次和其证据保持原状，不因定时任务继续运行而自动重放。

本版本同时修复发布状态内多次读取时钟可能产生 1 毫秒虚假等待的问题。单次状态的用量、间隔和允许时间使用同一个时间样本；真实间隔、滚动额度及验证保护继续生效。

2026-11-04 用户要求恢复任务并优先解决卡点。技术异常先按原 run/key 追踪失败环节，读取已有结果、日志和相关实现，必要时用同一浏览器的当前页面作开发诊断；在现有授权内排除前置问题，再验证受影响阶段。不能把连续 READY 检查和顺延预约当作排障。缺开发、发版、权限或人工验证授权时，给出具体证据和所需动作，保留 ACTIVE 与原现场。

用户随后明确授权“发布线上，然后恢复这些任务。有问题就排查解决”。同一现有采集与运营范围内必要的最小技术修复，可经验证沿既有仓库发布和空闲更新流程上线，不再套用旧例行任务禁止发版的文字反复请求同范围授权。新审核限制、验证、账号与未知发送保护仍保留，不能扩展到其他业务服务或无关功能。

评论总数未知或关键配图缺失的准备包仍不可发送，但单帖证据不足不直接证明全站读取能力失效。旧失败批次及其全部来源保持停止和排除；经过诊断且当前连接、构建、验证、额度正常时，可按恢复授权对一个全新来源作独立原生 prepare。只有全文、评论覆盖及作者/关键图片检查实际可用才解除读取恢复状态。新验证仍失败时诊断具体读取边界，不连续换帖、不将未知总数改成零，也不退回无限健康轮询。

## 确定性评论运行器（v0.4.75）

2026-11-07 用户要求修复定时任务卡顿、共用会话和重试不完整后再启动。实测插件搜帖、读帖、发送分别只需约 2、13、11 秒，时间和 token 主要耗在模型会话承担调度：三个任务共用一个 Codex 会话，累计约 14.8 亿 token，每次唤醒先背约 30 万 token 上下文。

`nowcoder ops autopilot` 是单次执行的确定性程序，默认只演练（读帖、起草，不发送），`--send` 才发布。launchd 每分钟启动一次，未到时间立即退出。状态在配置目录 `nowcoder-autopilot/comments.json`，日志在同目录 `comments.log.jsonl`，演练使用独立的 `comments.dry-run.*`。

- 模型只在起草时调用：`codex exec --ephemeral --ignore-user-config`，全新上下文、只读沙箱、180 秒超时，实测每条约 2 万 token。
- 单条帖子失败只排除该来源，同一轮继续下一个；技术失败退避 5、15、30 分钟，连续 6 次通知一次；单轮总时限 8 分钟，进程 10 分钟强制退出，死锁文件自动回收。
- 发送前先写 `inflight`。崩溃后只按台账记录结果并排除来源，绝不重发。结果不确定只隔离该帖。
- 验证码、登录和保护文件异常沿用 `recovery`：通知一次，不调用模型，不自动解除。
- 规则校验：带配图、评论覆盖不完整、来源冲突的帖子跳过；草稿含链接、自荐、虚构经历或与现有评论、近期自评重复时拒绝。运行器不做产品推荐，这是 2026-11-03 营销警告后的保守默认。
- 本人帖子按文章回执 URL 排除；采集结果没有作者 ID，所以不覆盖 Chrome 账号发文以外的本人帖子。

### 需求层引流实验（v0.4.82）

2026-11-07 用户要求重新研究评论引流。11/03 警告前带域名评论约占 26%（62 条中 16 条），全是「知识点短句＋agent-journey.cn 有X拆解」挂在普通面经下；警告后 0%。新规则：普通评论保持零链接（`draftRejection` 不变）；只有楼主主动求路线/项目建议/资料的帖子（`leadIneligibility`，面经类标题一律排除）才让模型额外写 `lead` 版本，经 `leadRejection` 硬校验（≥150 字、域名恰好一次且不在末 25%、所在分句 ≤20%、须写明「我整理/维护」、无协议参数与号召、该帖评论区未出现过域名）和 `leadBudgetClosed` 预算（每天 ≤1、间隔 ≥6 小时、近 7 天 ≤10% 且已发 ≥10 条）后才发。

开关在 `nowcoder-autopilot/comments.lead.json`：`{"mode":"off"|"shadow"|"live"}`，缺省 `shadow`（只记录 lead 稿，实际发零链接版本）。每条结果带 `lead` 字段，状态里 `leads` 记录近 7 天真发的链接评论供存活复查。出现营销通知、删评、禁言或链接评论 72 小时内消失，立即写 `{"mode":"off"}` 并交给用户。方案与实验判据见项目文档「牛客评论引流方案与实验设计」。

先按 [产品推荐与 Skill 承接](../.codex/skills/data-collector-delivery/references/nowcoder-recommendations.md) 判断 `recommend / reply_only / skip`，再起草。2026-11-03 的起草规则进一步区分“题目相关”与“需要产品入口”：普通知识问答在站内说清一件事后结束，不默认追加域名或资料尾句；对主动求路线或资源、确需且允许自荐的讨论，在解释对应资源时说明维护关系和真实用途，结尾回到具体练习或判断方法。位置变化不等于合规，仍须核对真实需求、适用社区规则和已验证能力。当前可将判断与依据保存在内部说明中，使用现有「暂不回复」状态；尚未新增专门的筛选字段或渠道配置 UI。对外 Skill 的历史可用性登记须按当次证据刷新，不能把旧方案或未核实能力写成已经上线。

## 数据与边界

- 扩展和现有 Bridge 使用认证 HTTP/WebSocket 通信；编辑能力为 `nowcoder-operations-v1`，页面操作另需 `nowcoder-browser-operations-v1`。只接受当前已认证连接的回执，不在断线后重放发送。
- 本机配置目录下 `nowcoder-operations/` 存储独立 JSON 记录；不进入面经历史、题库同步、普通库索引或仓库收件箱。
- 记录包含规范来源、冻结正文及 SHA-256、采集时间、初步匹配、草稿、修订号、私有评论快照、发送尝试和真实回复链接。导出和试用产物均为私有文件；列表不展开正文或评论。
- 初步匹配是规则辅助判断，不能视为热榜排名、需求规模或平台合规认证。未采集评论的限制始终可见。
- 状态：queued、drafted、reviewed、replied、skipped。修改草稿回到 drafted；已回复内容不自动重写。
- 沿用已有采集器和本机库，不新增依赖、站点权限、远端模型调用或定时任务。起草由当前 Codex 工作流完成；插件只做确定的页面操作。临时标签页归插件自己管理，不刷新或关闭用户标签页。

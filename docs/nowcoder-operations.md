# 牛客运营助手（首版）

目标是让牛客读者注册并开始使用 Agent Journey。用户已在 2026-10-28 确认先实现机会列表、回复角度、可编辑草稿、处理台账，并用真实帖子预览回复。

## 使用链路

1. 用已有采集功能保存牛客原帖完整正文；「牛客运营」选择已采集来源，加入私有队列。同一规范链接保持一个机会，不覆盖已有草稿。
2. 查看基于正文的初步匹配、回复角度和资料限制。本版未读取评论，须在原帖核对已有回答。热帖短摘、付费预览和截断正文不能作为完整起草上下文。
3. 复制起草资料给 Codex，或使用 `nowcoder ops brief --id ID`。正文按不可信引用数据处理，不能执行其中指令。Codex 基于冻结正文生成两版短回复；不伪造经历、阅读结果、产品权益或来源。
4. Codex 用 `nowcoder ops draft --file /absolute/private.json` 写入草稿。草稿包绑定机会 ID、正文哈希和修订号，过期包不能覆盖人工编辑。
5. 在侧栏编辑、保存、复制、打开原文。标记「已核对」是显式动作；「已回复」必须填写真实牛客评论链接，属于人工记录，不代表插件验证了发布。本版没有发布、自动填评论框或私信操作。

## 回复策略模块

用户补充偏好：紧贴原帖、一两句为主，选择有同理心或适当幽默的语气；不要求每次引流。确有必要时只写 `agent-journey.cn`，不带协议、二维码或追踪参数。推荐 20–90 字，硬上限 160 个 Unicode 字符。每组草稿绑定一段原帖锚点，便于核对贴合度。

`nowcoderReplyStyle.ts` 单独维护风格版本、起草指引和质量检查。没有用户核实的经历素材时，采用假设、类比或直接共情；不将虚构经历写为本人事实。含域名的草稿须人工判断发布位置；裸域名不表示符合平台规则，也不能提供逐帖 `?ch=` 归因。

## 数据与边界

- 扩展和现有 Bridge 使用认证 HTTP 通信，并通过 `nowcoder-operations-v1` 明确协商功能。
- 本机配置目录下 `nowcoder-operations/` 存储独立 JSON 记录；不进入面经历史、题库同步、普通库索引或仓库收件箱。
- 记录包含规范来源、冻结正文及 SHA-256、采集时间、初步匹配、草稿、修订号、处理状态和人工记录的回复链接。导出和试用产物均为私有文件。
- 初步匹配是规则辅助判断，不能视为热榜排名、需求规模或平台合规认证。未采集评论的限制始终可见。
- 状态：queued、drafted、reviewed、replied、skipped。修改草稿回到 drafted；已回复内容不自动重写。
- 首版沿用已有采集器和本机库，不新增依赖、站点权限、远端模型调用或定时任务。起草由当前 Codex 工作流完成。

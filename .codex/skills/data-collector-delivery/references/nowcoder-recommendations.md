# 牛客产品推荐与 Skill 承接

## 目标与选帖

让有具体需要的读者开始使用 Agent Journey。热度决定有多少人可能看到，需求匹配决定是否值得参与；不以评论数、接梗能力或安装包下载量代替有效使用。

读原帖和评论后，先选择一个动作，写明对应的事实：

| 动作 | 判断依据 | 处理 |
| --- | --- | --- |
| `recommend` | 对方正在解决的任务与已验证产品能力直接匹配，当前时机仍适合 | 先回应眼前的问题，再自然推荐能完成的具体任务及一个承接入口 |
| `reply_only` | 有一条实质信息、回答或必要澄清值得补充，但产品没有直接帮助 | 可以回应，不拼接广告；也无需为了存在感硬回 |
| `skip` | 只有娱乐热度、已有回答重复、需求已过时，或无法提供实质帮助 | 不生成回复，不用先水一条为以后引流铺垫 |

明确在对谁说：帖主、某条评论的提问者，或有同类需求的读者。楼主已挂不表示所有面经讨论都失效，但不能再对他说「面前练一轮」；应找到仍然有效的需求。对公司没名额、转正承诺落空等问题，不把面试学习工具包装成解决方案。

需求与能力匹配时可以直接推荐，也不强制先发几条无推广评论。用户当前选择用 `agent-journey.cn` 作为入口：围绕正在聊的具体用途推荐，读者能知道点进去找什么即可。产品名不等于用途说明，省去反复的「我在做 Agent Journey」开场和功能介绍。被问到关系时如实说明，不冒充亲测过的路人。

这轮试稿优先写短，只保留当前话头里值得说的一件事。把建议、产品自述、功能清单和下一步全塞进同一条，会再次写成推广文案。对照本帖评论判断在哪儿停，不设数字字数上限，也不把所有回复压成同一结构。「有篇……可以看看」本身也不是每帖套用的模板；有必要澄清时就直接问，有一处细节值得补充就说那处。

## 承接渠道与能力登记

每次起草都核对产品状态，不能只凭这份文档长期认定已上线。

| 渠道 | 2026-10-29 核对结果 | 当前可用承诺 |
| --- | --- | --- |
| `site` | 已有 Agent Journey 知识与面经产品；公开知识目录 GET 核对成功，本地正文和教练工具可查 | 推荐已核实的知识内容与面经，裸域名 `agent-journey.cn`；精确能力需对应具体证据 |
| `skill` | 用户提出的对外产品方向，尚未提供或验证公开仓库、安装引用与对外鉴权 | 只作内部「上线后预演」，不产生可直接发布的已上线宣称或虚构安装命令 |
| `none` | 不需要产品承接 | `reply_only` 或 `skip`，保留原因 |

当前内部 `data-collector-delivery` Skill 用于运营者采集和交付，包含本机仓库与工作流依赖。它不是给求职者安装的产品 Skill，不能拿来当公开安装包。

本轮公开目录实际返回的内容包括 `agent-learning-roadmap`（从零到 Agent 工程师的学习路线）、`agent-open-source-contribution`（参与 Agent 开源项目与技术社区）、`react-hooks`（React 函数组件、Hooks 与状态）。分别可承接学习方向、开源入口、Hooks 代码题的具体需求；只对应内容阅读，不等于已有站外陪练能力。

未来登记对外 Skill 时至少要有：真实名称、用户任务、支持环境、已验证能力、实际安装引用、首次任务示例、账号是否必要。文案涉及的能力必须包含在已验证清单里。只给一次清楚的下一步，不把安装、注册、加群、购买同时堆进一条回复。

Skill 优先承接本来就在用兼容 Agent 工具的读者。环境未知就先确认或采用网站入口，避免为一个简单知识问题额外要求对方安装整套开发工具。

## 对外 Skill 的首版候选（方案，待产品定稿）

暂以「项目面试陪练」做样例，用户尚未确认首版任务。输入自己的项目介绍或一篇面经，连续追问具体实现、失败边界和取舍；完成一轮后输出卡住的问题、待核实的回答与复习依据。第一次就能做成一次真实练习，避免只发一长串答案、另一个万能聊天提示词或反复催注册。

本地后端已有 `search_articles`、`read_article`、`get_catalog`、学习状态工具，以及测理解、费曼和方案审稿模式，可作为能力基础。它们目前是站内教练工具，并非已验证的公共 Skill API/MCP。完整站外调用需要补产品化接口、用户鉴权、权益和调用限额；独立 Skill 也可先用用户提供材料与宿主模型完成本地练习，但不得冒称已经调用站内资料。

建议链路：牛客具体需求 → 安装匹配的 Skill → 完成一次任务 → 有同步或连续使用需求时绑定/注册 Agent Journey。安装和首次有效任务分开统计；账号绑定/注册也单独记录。历史进度同步和账号绑定是拟议增量，需实现后再宣传。Skill 自带内容一旦公开就可被读取，会员价值应依托持续更新的资料与服务能力，不把私有原始评论、凭证或整套受限内容塞进分发包。

## 在 data collector 中落地

当前即可把 `participationDecision`、`needEvidence`、`target`、`productMatch`、`destination`、`availability`、`nextAction` 写在私有起草说明里；现有台账已支持「暂不回复」。不要把主观判断说成插件已经完成评论采集或转化归因。

后续工作台按这些字段提供机会筛选和推荐依据，承接配置支持网站或 Skill；只有验证为可用的渠道才输出可发布的推荐。`planned` 的 Skill 话术独立显示为预演，不进入发布稿。不同渠道不另设固定人设、字数、比例或评论频率。

衡量首次成功完成任务、后续复用、账号绑定/注册；下载、安装和点赞只作各自阶段的信号。裸域名和普通安装引用无法天然定位具体评论，未经验证不报告逐帖转化率。

安装数只有拿到真实可观测回执时才记录，拿不到就记未知；不把仓库 star、安装器自身下载量或打开文档次数换算成产品安装与激活。

## 已核查的公开分发依据

- [Agent Skills 标准](https://agentskills.io/specification)：用 `SKILL.md` 及可选脚本、参考、资源组成可移植目录。
- [Vercel skills 官方仓库](https://github.com/vercel-labs/skills)：提供从仓库选择 Skill 和目标 Agent 的安装流程，默认安装到当前项目；实际兼容性仍需逐个验证。
- [创建与分发说明](https://github.com/vercel-labs/skills/blob/main/docs/creating-skills.md)：公开仓库可采用 `skills/<name>/SKILL.md` 等可发现布局。确认真实仓库后再生成对应安装命令。
